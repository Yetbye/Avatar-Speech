01 一句话读懂：从「先声后画」到「音画同生」

Audio-Video joint generation 要回答的唯一核心问题是：声音与画面应该在流水线的哪一步相遇？传统级联把相遇推迟到最后——先有台词、再有语音、最后让视频模型对口型；而这一谱系上的工作（OmniVAE、AVTok、NAVA、MOVA、Ovi、LTX-2、UniAVGen、Soundwich）把相遇提前到表示层、去噪过程甚至推理控制层，让音画在同一个生成过程里共同演化。本页按「表示层 → 融合层 → 控制层」三层展开这条谱系。

先看两条范式的流水线对比。串行范式（sequential）的每一步都独立优化，误差逐级传播；联合范式（joint）把视频与语音放进同一个去噪/生成过程，时间轴天然共享：

串行级联（sequential）：

Text→TTS→Speech→VidGen→Video

联合生成（joint）：

Vid + Speech 条件→Joint 联合生成→Video ⊕ Audio
图 1 · 串行级联 vs 联合生成范式对比。它把「音画在哪一步相遇」这个抽象问题具象化为两条流水线：上排的同步是 VidGen 阶段的事后约束，下排的同步内生于联合去噪过程。
深度洞察

「联合」不是一个开关，而是一个连续谱

把这条谱系粗读成「联合 vs 级联」二分法会错失真正的设计空间。笔记中的八项工作实际在三个层次上分别「联合」：表示层（OmniVAE 的对齐蒸馏、AVTok 的共享 codebook）、生成层（MOVA/Ovi/LTX-2/UniAVGen 的双流交互、NAVA 的共享融合）、控制层（Soundwich 的逐声源 guidance）。同一件工作可以同时占多层——例如 AVTok 既是统一 tokenizer（表示层）又配自回归生成先验（生成层）。判断一个方案的「联合程度」，应分别问：latent 是否共享？参数是否共享？时间轴如何对齐？噪声过程是否耦合？这四个问题构成后文所有模型卡片的统一读法。

02 表示层路线：统一/对齐表示（OmniVAE · AVTok）

第一条路线把跨模态问题前移到表示层：如果音视频 latent 本身就对齐、可重建、语义一致，下游生成器就只需要学「画音同步的分布」，而不用同时学「两个模态如何互相翻译」。代表工作是 OmniVAE 与 AVTok——两者对「共享到什么程度」给出了相反的答案。

OmniVAE：各自重建，用对齐损失与语义蒸馏建立共享语义坐标

方法
在表示层学习音视频对齐：保留音频和视频各自的 VAE，在 latent 上加入片段级双向对比学习，并从预训练语义编码器蒸馏模态知识，让下游生成器获得更容易学习的表示。
Latent 与解码
两路保留各自可重建的 latent，通过共享语义坐标建立细粒度对应；下游 DiT 生成音视频 latent，再由各自 decoder 还原。替代方案：把两路压进同一组联合隐变量——AVTok 的 Vanilla 实验表明这条路重建表现更差。
训练与前置
需要同步配对片段、重建目标和冻结语义教师；先训练/适配 VAE，再验证下游生成。对比学习与语义蒸馏属于训练阶段目标。
优势与证据
论文通过 latent 同步探测与下游 T2AV 实验，报告语义蒸馏和片段级对齐的互补收益：二者结合提升生成质量与同步。

AVTok：统一 tokenizer/codebook，但保留模态专属 token 序列

方法
统一音视频 tokenizer：视频与音频频谱分别切块，经可学习查询压缩为一维离散 token；两路共享编解码器主干和码本，保留各自的查询、归一化层和 token 序列。生成阶段用自回归模型预测 token，再解码为视频和音频。
Latent 与解码
音视频使用模态各自的 token 序列，共享编解码器主干与码本；视频 token 还原画面，音频 token 还原频谱并经声码器输出波形。替代方案：初始 Vanilla 版本使用同一组联合隐变量——共享 latent、共享参数效果不好，最终双流版本重建更好（笔记旁注）。
训练与前置
需要成对音视频重建数据；采用 VFAL 分阶段训练：先视频、再音频、最后微调解码器，并加入特征对齐与自回归预测目标。先检查压缩、重建和模态信息平衡，再训练下游生成器。
优势与证据
论文比较 Vanilla 与双流设计，报告双流重建更好，并验证音到视频、视频到音频和类别条件联合生成。未决：指定台词与复杂声景可作为后续验证项。
图 2 · 「统一表示 vs 分离表示」的范式对比。它把「latent 该共享到什么程度」具象化为一条从左到右的谱系，AVTok 的 Vanilla 失败与 OmniVAE 的对齐收益分别钉住谱系两端。
深度洞察

表示层路线与双流路线并不互斥，而是分工

OmniVAE/AVTok 解决的是「让 latent 好学」，MOVA/Ovi 等双流路线解决的是「让生成过程耦合」。前者把跨模态一致性固化进表示（训练期一次性付出），后者把它留给注意力交互（生成期逐层付出）。自然的推论是：OmniVAE 式的对齐蒸馏可以作为双流生成器的 latent 空间初始化或辅助目标——笔记中 OmniVAE 验证的正是「表示对齐 → 下游 T2AV 变容易」这一传导路径，而双流模型普遍还要在训练中重新学对齐。二者叠加是否还有边际收益，是本页科研问题 Q1 的落点。

批判评估

表示层路线的证据止步于「更容易学习」，而非「最终质量更好」

OmniVAE 的证据是 latent 同步探测与下游 T2AV 实验，AVTok 的证据是重建质量与三类生成任务（A2V、V2A、类别条件）。两者都没有给出指定台词（scripted speech）与复杂声景下的结果——笔记明确把这两项列为「后续验证项」。换言之，表示层对齐的收益在「自由生成」设定下成立，但在数字人场景真正需要的「台词驱动 + 复杂声景」设定下仍是空白。

03 融合层路线 A：先对齐后共享融合（NAVA）

第二条路线不改动 latent，而是重组生成网络内部的分工。NAVA 的 Align-then-Fuse MMDiT 是这条路线的单点突破：前部层在专门空间建立音视频对应关系，后部层共享参数联合去噪——把「对齐」和「融合」显式拆成两个阶段，而不是指望注意力自己学出对齐。

方法
Align-then-Fuse MMDiT：前部层在专门空间建立音视频对应关系，后部层共享参数联合去噪；文本与参考音色作为外部上下文。Timbre-in-Context Conditioning 将音色条件绑定到具体台词片段。
Latent 与解码
输入音视频 latent，经过模态感知对齐后进入共享融合层；输出仍通过对应的视频与音频 VAE 解码。替代方案：全程共享参数（MMDiT 原生做法）或全程分离（纯双塔）——NAVA 的消融对齐与融合设计做了对照。
训练与前置
复用 Wan 视频骨干与视频 VAE、LTX 音频 VAE；渐进混合音频单模态与配对音视频训练，再在高质量数据上微调，并使用跨模态注意力与音色条件 dropout。
优势与证据
论文在 Verse-Bench、Seed-TTS 和人评中报告声画同步、视觉质量及音色控制的收益，并消融对齐与融合设计。
图 3 · NAVA 的 Align-then-Fuse 架构流。它把「模态专属对齐与共享生成如何衔接」这一抽象问题具象化为一条前后分工的网络：对齐层与融合层各司其职，外部上下文（文本/音色）旁路注入。

这条路线的设计哲学值得注意：MMDiT 的全共享参数默认假设「对齐会在共享空间里自然涌现」，而 NAVA 认为对齐需要专门空间 + 专门层。这与 OmniVAE 在表示层的判断同构——对齐是需要被显式监督/显式结构化的对象，不应放任其自发形成。两者的差别只在作用位置：OmniVAE 作用在 latent 进入网络之前，NAVA 作用在网络内部。

深度洞察

「音色条件 dropout」是可控性与生成质量的经典权衡

NAVA 在训练中对音色条件做 dropout，本质是让模型同时学「有条件」与「无条件」两条生成路径——这是把 CFG 式推理控制内化为训练目标的做法。它的代价是训练数据要覆盖两种模式（笔记提到渐进混合音频单模态与配对音视频训练），收益是推理期可以分别调节文本遵循与音色绑定强度。对比 LTX-2/UniAVGen 直接在推理期用模态感知 CFG 调节，NAVA 的做法更贵但更稳；两种方案孰优孰劣，取决于下游是否需要精细的音色编辑——这正是 Q4 的变量之一。

04 融合层路线 B：双流/双塔联合生成（MOVA · Ovi · LTX-2 · UniAVGen）

第三条路线是本谱系的主力：两个模态各自保留骨干，靠交互模块在去噪过程中交换信息。四个代表工作的差异集中在三点——双塔是否对称、交互发生在哪一层、时间轴如何对齐。

MOVA：双塔 + Bridge Cross-Attention + Aligned RoPE

方法
双塔：Wan2.2 视频 DiT 与 1.3B 音频 DiT 在文本条件下联合去噪，通过双向 Bridge Cross-Attention 交换特征；Aligned RoPE 将两路位置映射到统一时间尺度以保证音画同步；最后由各自 VAE 解码，输出视频及语音、音效和音乐。
Latent 与解码
视频与音频保留各自 latent，通过 Bridge 在生成过程中交互；时间位置编码统一到物理时间轴，最终分别解码为视频和含 speech、音效、音乐的完整音轨。笔记旁注：audio 的 latent 要远远稠密 video 的 latent——两塔的信息密度天然不对称。
训练与前置
先建立音频塔的生成能力，再联合训练双塔与 Bridge。Bridge 和骨干采用差异学习率，音视频采用可分别调节的噪声调度；需同步音视频、准确台词和声景描述。
优势与证据
论文提供语音、音画对齐及人评，并对推理控制开展消融。冻结双塔的暖启动在作者实验中较早达到平台，最终采用联合更新（第 4.4 节）。

Ovi：对称双 DiT + 逐层双向 Cross-Attention

方法
对称双 DiT 骨干：视频分支由 Wan2.2-5B 初始化，音频分支采用匹配架构；每层通过双向 Cross-Attention 交换信息，使用缩放 RoPE 对齐时间。场景、台词和声音描述组成共享文本条件。
Latent 与解码
视频与音频分别编码、联合去噪。视频用 Wan VAE；音频用 MMAudio 的 VAE，latent 解码成频谱，再经 BigVGAN 输出波形。替代方案：MOVA 的 Bridge 只在特定层交换，Ovi 每层都交换——交互更密集，但每层注意力成本更高。
训练与前置
先预训练音频塔并补充音效数据，再在同步音视频上训练融合；融合阶段冻结 FFN，更新单模态与跨模态注意力。前置包括通用音频能力、同步过滤和含台词的声景描述。
优势与证据
作者在 Verse-Bench 人评中报告相对 JavisDiT、UniVerse-1 的音视频质量与同步偏好优势——这是联合模型之间的比较，而非与级联基线比较。

LTX-2：非对称双流 + 模态感知 CFG

方法
非对称双流 Transformer，原始报告中视频流 14B、音频流 5B；通过双向音视频注意力、时间位置编码与共享噪声条件联合生成。模态感知 CFG 分别控制文本遵循与声画关联。
Latent 与解码
音视频各自保留 VAE latent，通过双流交互共同演化，分别解码输出画面和包含 speech、环境声及拟音（Foley）的音轨。14B/5B 的非对称比例与 MOVA 的 latent 稠密性观察一致：视频侧需要更大容量。
训练与前置
训练数据需要同步视频、音轨和完整 caption：包含台词、说话人、语言、口音与环境声音；双流骨干和文本连接模块共同训练。
优势与证据
原始报告提供音视频人评和跨模态 guidance 分析；作者观察到增强跨模态 guidance 可改善同步与语义一致性。

UniAVGen：非对称时间对齐交互 + Face-Aware Modulation

方法
音视频双分支联合生成，加入非对称时间对齐交互：音频线索指导口型和动作，视觉线索帮助声音匹配表情与身份；通过 Face-Aware Modulation 聚焦人脸，并用模态感知 CFG 控制跨模态关联。
Latent 与解码
视频采用 Wan VAE latent；音频采用 Mel 频谱表示并由声码器还原。支持参考图像、指定台词和可选参考声音。音频侧走 Mel 而非离散 token，与 UniTalking 同路，属于「频谱 + 声码器」解码家族。
训练与前置
先训练音频分支，再在真实配对音视频上联合更新，随后开展多任务训练：联合生成、续写、配音和音频驱动视频。
优势与证据
表 1 中，相对 F5-TTS＋OmniAvatar：情绪一致性 0.573/0.349，音频质量 PQ 7.00/8.15，口型分 5.95/6.34。情绪一致性使用多模态模型评分，笔记认为值得补充人类盲评。注意三个指标方向不一致：情绪赢，音质与口型输——见本页批判评估。
图 4 · 双流联合生成的公共骨架：两支骨干 + 双向交互 + 统一时间轴 + 各自解码。四个代表工作的全部分歧都落在「交互在哪层」「时间轴怎么对齐」「两塔是否对称」这三个维度上。
Eq.1 · 双流联合去噪目标（示意性形式化，非论文原式）
$$ \mathcal{L}_{\text{joint}} = \mathbb{E}_{t}\Big[\|v^{V}_{\theta}(z^{V}_{t}, t, \mathrm{Attn}(z^{A}_{t})) - (z^{V}_{1}-z^{V}_{0})\|^{2} + \|v^{A}_{\theta}(z^{A}_{t}, t, \mathrm{Attn}(z^{V}_{t})) - (z^{A}_{1}-z^{A}_{0})\|^{2}\Big] $$
直觉：两路 Flow Matching 速度场各自回归自己的目标（$z^V$ 视频 latent、$z^A$ 音频 latent），但每个速度场的条件里都含对方当前状态经注意力（Bridge / 逐层 Cross-Attention）送来的信息——耦合项 $\mathrm{Attn}(\cdot)$ 就是「联合」的全部含义。MOVA 的 Bridge、Ovi 的逐层交互、LTX-2 的双向注意力都可视为这个耦合项的不同实现；UniTalking/JoVA 则更进一步，把两路 token 拼接后做 Joint Attention（见语音-视频页）。此式为本页对笔记描述的示意性归纳，系数与符号不对应任何论文原文。

跨论文连接：四个工作在训练次序上高度收敛——都先建立音频侧的生成能力，再做联合训练（MOVA「先建立音频塔」、Ovi「先预训练音频塔」、UniAVGen「先训练音频分支」；语音-视频页的 UniTalking/JoVA 同样先训音频分支）。这不是巧合：视频骨干有 Wan 等强预训练，音频塔起点低，而笔记标注 audio latent 又远比 video latent 稠密——冷启动不足的音频塔会在联合训练早期拖垮同步。

批判评估

联合更新 vs 冻结暖启动：MOVA 的实测给出了反直觉答案

MOVA 的消融显示冻结双塔的暖启动较早达到平台，最终采用联合更新（第 4.4 节）。这说明「先冻结后解冻」这一迁移学习常识在双流联合生成里可能不成立：Bridge 需要与两侧骨干协同塑形，冻结骨干会把 Bridge 锁死在次优接口上。代价是联合更新的训练成本与不稳定风险更高（差异学习率、可分别调节的噪声调度都是为此打的补丁）。另一个被掩盖的代价是：四个工作各自的 benchmark 不互通（Verse-Bench、JoVABench-Gen、表 1 自建指标），跨工作横向比较目前只能靠人评口径。

05 控制层路线：多声源分轨（Soundwich）

前两条路线都把音轨当作一条整体信号；Soundwich 把问题改写为：speech、背景声与音效如何同步生成并独立编辑？它的答案极其取巧——在冻结的原生音视频模型上扩展多条音频生成轨迹，保留同一视频轨迹，全程 training-free。

方法
在冻结的原生音视频模型上扩展多条音频生成轨迹，保留同一视频轨迹；通过共享场景信息、逐声源 guidance、时间控制与实体注意力路由，输出分别可编辑的人声、音效和背景声。
Latent 与解码
多个声源各有音频 latent，视觉端共享视频 latent；音轨分别解码，再按需求混音，支持静音、替换、重排和单独调节。替代方案：Unison 在训练期就显式建模 speech/SFX 两路 latent（见语音-视频页）——训练期分轨 vs 推理期分轨是两种哲学。
训练与前置
采用 training-free 推理改造，复用已有联合生成器；前置包括源级声音条件、可选时间窗口，以及可见声源的分割/实体对应。
优势与证据
论文实验与人评报告时间控制、音源分离和自然度方面的改善，并通过组件消融分析场景广播与实体路由两个模块。
图 5 · 多声源分轨示意：Soundwich 把「一条音轨」展开为多条按声源分轨的音频轨迹，共享同一视频轨迹，各轨独立解码后按需混音——把「同步生成 + 独立编辑」这对矛盾拆到轨迹结构里解决。
深度洞察

Soundwich 的真正贡献是「控制层解耦」，而非生成能力

Soundwich 不改进生成质量本身，而是把 per-source guidance、时间窗口、实体路由三个控制旋钮放到推理期。它的存在证明：现有联合生成器内部已经蕴含可分解的多声源信息，缺的只是把它「路由」出来的机制。这也改变了对前面各路线的评价标准——当分轨可以在推理期近乎免费地获得（training-free），训练期显式分轨（Unison 的 speech/SFX 双 latent）的价值就要重新论证：训练期分轨的不可替代收益究竟在哪里？可能的答案是生成质量上限与不可见声源的鲁棒性（Soundwich 前置要求「可见声源的分割/实体对应」），但笔记中没有直接对照实验，这属于开放问题。

07 深度洞察 & 批判评估

深度洞察

「音频塔冷启动」是全谱系的隐藏共识

MOVA「先建立音频塔的生成能力」、Ovi「先预训练音频塔并补充音效数据」、UniAVGen「先训练音频分支」——三个双流工作不约而同采用同一训练次序。背后是结构性不对称：视频侧有 Wan2.2 等强预训练骨干直接复用，音频侧往往只是「匹配架构」从头或半头训练，且音频 latent 稠密度更高。这意味着当前所谓「联合生成」在实践中常是「预训练好的视频塔 + 冷启动的音频塔 + 中途焊接的交互模块」。谁先做出音频侧等价于 Wan 的强预训练基座，谁就能改写这条路线的成本结构——这是比继续堆交互模块更根本的机会。

深度洞察

同步的监督信号正在从「全局」下沉到「局部」

同步的显式建模经历了清晰的下沉轨迹：OmniVAE 的片段级对比 → 时间 RoPE/Aligned RoPE 的位置级对齐（MOVA/Ovi）→ UniAVGen 的人脸区域调制（Face-Aware Modulation）。每一级都把监督粒度往「嘴部/面部」这样的局部语义推进。理论上，全局指标（如同步判别器）对「嘴型是否对上音节」只有间接约束，局部监督才是直接约束——但局部监督需要额外前置（口型/人脸标注，如 JoVA 的嘴部关键点，见语音-视频页），这是质量与数据成本的交换。

批判评估

证据体系的三处裂缝

其一，指标不互通：Verse-Bench、Seed-TTS、JoVABench-Gen、各论文自建表 1 分头使用，跨工作排序只能靠人评口径间接推断。其二，指标由模型打分的比例偏高：UniAVGen 的情绪一致性由多模态模型评分，笔记原话「值得补充人类盲评」。其三，联合模型的胜负手未必在「联合」：UniAVGen 相对 F5-TTS＋OmniAvatar 情绪一致性 0.573 vs 0.349 大胜，但音频 PQ 7.00 vs 8.15、口型 5.95 vs 6.34 反而落后——在纯音质和纯口型这两项上，级联基线仍然更强。联合生成目前更强的是情绪/语义一致性，不是逐项保真。

批判评估

training-free 的天花板与前置负担

Soundwich 的零训练成本是卖点，但前置并不轻：源级声音条件、时间窗口指定、可见声源的分割/实体对应。当声源不可见（画外音、环境声）或实体对应歧义时，实体注意力路由失去锚点——笔记未报告该失败模式的处理。更根本地，training-free 改造的效果上限被冻结的原生生成器锁死：若基座的多声源信息本来就纠缠，推理期路由分轨只能解耦「可分解」的部分。

08 自主科研问题

自主科研问题 · Q1

表示共享程度的最优点在哪里？

未知与意义：AVTok 的 Vanilla（共享联合隐变量）失败、双流（共享码本+专属 token）成功，OmniVAE（完全分离+对齐损失）也成功——但三者不在同一评测口径下，「共享程度-性能」曲线的真实形状未知。若曲线存在清晰最优点，整个表示层路线可以被参数化设计而非逐案试错。

理论分析：可从模态信息平衡切入：共享 latent 要求同一组比特同时最小化两模态的重建误差，当音视频熵不匹配（笔记：audio latent 远稠密于 video latent）时，共享码率会被高熵模态主导，低熵模态重建受损——这与 AVTok 观察到的 Vanilla 重建更差一致。

连接：AVTok 的 VFAL 分阶段训练、OmniVAE 的「重建目标 + 对齐目标」双目标、MOVA 的稠密性旁注。

探究方向：固定数据与生成器，扫四个档位（共享 latent / 共享 codebook / 共享主干 / 全分离+对比），分别测重建质量、latent 同步探测、下游 T2AV 与指定台词生成，画出完整权衡曲线。

自主科研问题 · Q2

音频塔冷启动能否被训练机制替代？

未知与意义：「先音频后联合」已是事实标准，但预训练次序是昂贵的课程设计。若可分离的噪声调度（MOVA）、差异学习率或模态感知 CFG 能补偿冷启动不足，训练管线可以大幅简化。

理论分析：联合训练早期，音频塔速度场误差大，通过交互模块反向污染视频塔的去噪轨迹；先训音频相当于把耦合项的输入「预热」到可信区间。替代机制的思路是让耦合项在早期自适应降权（课程式开启 Bridge）。

连接：MOVA「冻结双塔暖启动较早达到平台、最终联合更新」的反直觉消融；Ovi 融合阶段冻结 FFN；LTX-2 共享噪声条件。

探究方向：对照四种次序（先音频/先视频/并行/课程式耦合开启），监控 Bridge 梯度范数与同步指标的时序曲线，定位「暖启动何时成为瓶颈」。

自主科研问题 · Q3

三种时间对齐机制（RoPE 族 / 片段对比 / 局部监督）谁在真正起作用？

未知与意义：Aligned RoPE、缩放 RoPE、时间 RoPE、片段级对比、人脸区域调制分别被各论文报告有效，但它们可能测的是同步的不同侧面（宏观漂移 vs 音节级口型），从无统一消融。

理论分析：位置编码类方法约束的是「时间戳映射」，对比/局部监督约束的是「内容对应」。前者解决漂移，后者解决错配；一个只做位置对齐的模型可能宏观同步好而音节级口型差。

连接：MOVA/Ovi 的 RoPE 设计、OmniVAE 的 latent 同步探测、UniAVGen 的口型分与情绪分分裂表现。

探究方向：构建分层同步评测（秒级漂移 / 音节级口型 / 语义一致），在同一双流基座上单独开关各机制，定位每种机制的作用层面。

自主科研问题 · Q4

多声源分轨：推理期路由 vs 训练期显式分轨，边界在哪里？

未知与意义：Soundwich 用 training-free 路由获得分轨编辑能力，而 Unison（见语音-视频页）在训练期显式建模 speech/SFX 双 latent。两条路线的成本-能力边界没有对照数据。

理论分析：推理期路由假设基座的多声源信息线性可分解，实体注意力路由以「可见声源」为锚；训练期显式分轨把分解写进表示，代价是需要 Mel-Roformer 式分离监督。画外声源、声源数量动态变化是两者的共同压力测试点。

连接：Soundwich 的场景广播与实体路由消融、Unison 的 Bi-ACA 与语义条件门控、AVTok 的「模态信息平衡」检查。

探究方向：在含画外音/动态声源数的场景上对比两路线的分离质量、编辑一致性与同步指标，并测「路由失败时的优雅降级」行为。

# 双流联合去噪（MOVA/Ovi/LTX-2 公共骨架的示意性归纳）
def joint_denoise(z_v, z_a, text_cond, steps):
    for t in timesteps(steps):
        # 双向交互：Bridge / 逐层 Cross-Attention（耦合项）
        m_v = cross_attn(z_v, z_a)   # 音频 → 视频线索
        m_a = cross_attn(z_a, z_v)   # 视频 → 音频线索
        # 时间对齐：Aligned RoPE 把两路位置映射到统一物理时间轴
        v_v = video_dit(z_v, t, cond=text_cond, mem=m_v, rope=aligned_rope)
        v_a = audio_dit(z_a, t, cond=text_cond, mem=m_a, rope=aligned_rope)
        z_v = euler_step(z_v, v_v, sigma_schedule_v(t))  # 可分别调节的噪声调度
        z_a = euler_step(z_a, v_a, sigma_schedule_a(t))
    video = video_vae.decode(z_v)
    audio = audio_vae.decode(z_a)    # 频谱 → BigVGAN/声码器 → 波形
    return video, audio

# Soundwich 式多声源分轨推理（training-free，示意）
def soundwich_multitrack(frozen_av_model, scene, sources):
    z_v = init_video_latent(scene)                # 一条共享视频轨迹
    tracks = []
    for src in sources:                          # 人声 / 音效 / 背景声
        z_a = init_audio_latent()
        for t in timesteps():
            # 共享场景信息 + 逐声源 guidance + 实体注意力路由
            z_a = step(z_a, t,
                       cond=scene_broadcast(scene),
                       guidance=per_source_guidance(src),
                       routing=entity_attention(src.visible_entities),
                       window=src.time_window)     # 可选时间控制
        tracks.append(audio_vae.decode(z_a))      # 各轨独立解码
