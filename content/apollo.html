01 一句话读懂：不做级联、不做双塔，只做一个塔

音视频联合生成有三条工程路线：级联（先生成视频再配音）、双塔（视频塔 + 音频塔互相看）、单塔（一个 Transformer 同时吃两种模态）。Apollo 的主张很硬：选第三条，并把它推到「一个模型覆盖全部任务」的程度——T2AV、TI2AV、TI2V、T2V、T2A 都由同一个单塔 DiT 承担。

论文把工作拆成三条轴，这个拆法本身值得学习：模型架构（单塔 unified DiT + Omni-Full Attention）、训练策略（渐进多任务：随机模态掩码 + 多阶段课程）、数据构造（首个带密集描述的大规模音视频数据集）。

T2AV· TI2AV· TI2V· T2V· T2A → 同一个单塔

02 三种框架的取舍：为什么单塔更难但更对

图 1 · 级联 / 双塔 / 单塔：Apollo 选第三种，并把它用于多任务统一
深度洞察

「单塔」的真正优势是多任务，而不是参数效率

很多人把单塔理解为「省参数」。Apollo 的论证重点其实在任务统一：当所有任务都变成「同一序列里放哪些 token」时，任务之间的知识可以互相迁移（视频生成学到的事件先验能帮到音频生成）。这正是它敢用随机模态掩码训练的原因——掩码在序列层面天然可定义，而在双塔结构里，掩掉一个塔的损失函数就不好写了。

03 Omni-Full Attention：让音视频 token 在同一张注意力图里互相看见

单塔的关键是实现「全注意力」：视频 token 与音频 token 拼成一条序列，一次注意力同时完成模态内与跨模态建模。论文称之为 Omni-Full Attention，并强调它带来「紧致的音画对齐」与「强可扩展性」。

04 训练策略：随机模态掩码 + 多阶段课程

单塔最大的坑是模态坍塌：当某一模态更易学时，共享参数会全部向它倾斜，另一模态退化为附属。Apollo 用两招对冲：

随机模态掩码
训练时随机丢弃某些模态的 token，迫使模型在不同输入组合下都能工作（T2V / T2A / T2AV 等）。与 BERT 的 mask 精神相似，但这里遮蔽的是整模态而非单个 token。
多阶段课程
从较弱/较短的任务起步，逐步加入更难、更长的联合任务，避免一开始就被跨模态对齐的难度压垮。替代方案：直接混合训练（更简单，但容易早期失衡）。
目标
论文明确列出三点：稳健表示、强化 A-V 对齐的世界知识、防止单模态坍塌。这三条正是单塔路线必须自证的地方。
数据侧配套
首个带密集描述的大规模音视频数据集 + 自动化构造管线（标注 + 过滤出数百万严格对齐的 AV-caption 三元组）。没有密集描述，联合训练的「说什么」就无从监督。
结构性手段，而非损失项修补。
图 3 · 随机模态掩码：让单塔在缺失模态时仍可推理
深度洞察

掩码本质是在训练分布上「制造缺失」，从而获得鲁棒性

这与多模态大模型里的 modality dropout 同源：推理时用户可能只给文本、只给音频或只给视频，模型必须对任意子集都定义良好。差别在于 Apollo 把它与「多任务统一」绑定——掩码决定了当前样本属于哪个任务，因此任务定义与训练正则合二为一。

在方法层面，Apollo 的价值不只是「又一个联合模型」，而是把「任务统一」作为一等目标：级联与双塔都难以在不改结构的前提下覆盖 5 个任务，单塔天然可以。这也是它与 Ovi（双塔、单任务联合生成）、LTX-2（非对称双流、偏基座）最本质的差别。

深度洞察

「单塔 + 掩码」让任务定义变成数据问题，而不是模型问题

在双塔结构里，加一个新任务往往意味着改损失、改头、改数据流；在单塔 + 随机掩码下，新任务只是「序列里放哪些 token 的一个新组合」。这把工程重心从模型改动转移到了数据配比——这是 Apollo 论文里最容易被低估的架构性收益。

批判评估

1. 「对标 Veo 3」缺乏受控条件

摘要给出「comparable to Veo 3」，但闭源模型的评测通常只能在作者自建提示集与自建人评上进行。没有公开的提示集、评分细则与样本量，这个结论的可复现性接近于零。合理的读法是「在作者设定下不落下风」。

批判评估

2. 单塔的注意力代价被低估

Omni-Full Attention 让序列变长（视频 + 音频 + 文本），注意力是平方代价。论文强调可扩展性，但没有给出「音视频 token 数增长时的算力曲线」。在长时长/高分辨率场景，这可能成为硬瓶颈——这也是 VDN 一类「混合注意力」工作存在的理由。

批判评估

3. 数据管线是核心贡献却最难验证

「密集描述 + 严格对齐」的数据是单塔多任务成立的前提，但数据构造细节（如何自动标注台词、如何过滤不同步样本）在公开文本中较为概括。这类贡献的可验证性天然弱于模型结构。

06 自主科研问题

自主科研问题 · Q1

单塔与双塔在「等算力」下的质量–扩展曲线谁更陡？

未知与意义：Apollo 主张单塔更可扩展，Ovi 主张双塔更好对齐。二者都未给出等算力、等数据的 scaling 对照。

理论分析：单塔把两模态放在同一注意力矩阵，等效于全连接跨模态图，表达力上界更高但样本复杂度也更高；双塔相当于对跨模态交互做了低秩约束（只在 AV-Cross 子层），是归纳偏置换样本效率。可用「跨模态交互的秩」来统一刻画两者。

连接：与 MOVA 的 Bridge（介于两者之间）、LTX-2 的非对称双流共同构成「交互密度」光谱。

探究方向：在相同 GPU·小时下比较 Apollo 单塔与 Ovi 双塔的 Sync/FD 曲线，并测数据量减半时的退化幅度。

自主科研问题 · Q2

模态掩码的概率分布是否应随训练进程变化？

未知与意义：固定掩码率是一种简化。若早期应多掩码（学单模态基础）、后期少掩码（学对齐），课程化掩码可能显著提升效率。

理论分析：可把掩码率 p(t) 视为对任务分布的非平稳采样。用多任务学习的梯度冲突理论，p(t) 应使各任务梯度余弦相似度在训练后期趋于一致——这给出可计算的调度准则。

连接：Apollo 已用「多阶段课程」，但课程作用于任务难度，未必作用于掩码率；这是可拆分的两个维度。

探究方向：对比固定 p 与线性/余弦 p(t) 调度，在相同步数下比较 T2AV 的 FVD 与 T2V 的保真度。

自主科研问题 · Q3

「无模态掩码」的注意力是否需要物理时间约束？

未知与意义：Omni-Full Attention 让音频 token 与视频 token 全可见，但两者时间分辨率不同。若不注入统一时间坐标，模型可能学到「伪相关」而非真实的时间对齐。

理论分析：设视频每帧对应 Δt_v、音频每 token 对应 Δt_a。若 Δt_a ≪ Δt_v，一个视频 token 会对上多个音频 token；全注意力在此处等价于对「一个视觉事件 ↔ 一段音频事件」做多对多匹配，缺乏单调性约束时容易塌缩成平均。

连接：Ovi 用 scaled-RoPE 把两路映射到统一时间尺度，MOVA 用 Aligned RoPE 做同样的事——说明「统一时间坐标」几乎是所有联合模型的必要组件。Apollo 的抽取文本未强调这一项，值得追问。

探究方向：在 Apollo 上对比「纯全注意力」与「全注意力 + 统一时间 RoPE」，用事件级 onset 偏差作为判据。

# 单塔序列构造 + Omni-Full Attention（依据论文 3.x 重建，非官方实现）
def build_sequence(video_tok, audio_tok, text_tok, mask):
    # mask: dict(video=bool, audio=bool, text=bool) —— 随机模态掩码
    parts, types = [], []
    if mask["text"]:  parts.append(text_tok);  types += [0] * text_tok.shape[1]
    if mask["video"]: parts.append(video_tok); types += [1] * video_tok.shape[1]
    if mask["audio"]: parts.append(audio_tok); types += [2] * audio_tok.shape[1]
    x = torch.cat(parts, dim=1)
    return x, torch.tensor(types)

class OmniFullAttention(nn.Module):
    def forward(self, x):
        # 无模态级 mask：所有权重对所有 token 可见（full attention）
        return F.scaled_dot_product_attention(x, x, x, is_causal=False)

4. 任务统一也有代价：单一损失难兼顾异质目标

音频的感知损失与视频的感知损失性质不同（一个对相位/瞬态敏感，一个对运动/结构敏感）。用一个共享塔 + 一套损失权重服务 5 个任务，意味着必须做折中；论文未给出按任务调权的消融，因此「统一不损性能」这一隐含主张仍需证据。
