01 白板总览：Sequential vs Joint 两大范式

本页把白板上的「音视频基础模型 → 语音-视频生成 → 任务角度分析 → 语音-音频对齐」四层结构逐模型展开：先用一条范式主线（级联式 Sequential vs 联合式 Joint）把全部工作放上地图，再逐个模型梳理方法/范式、Latent 与解码、训练与前置、优势与证据、路线定位，最后落到两条交叉分析维度。事实以 web_landscape.json（已核对 arXiv 索引）、路线笔记（AVG.txt / vidgen.txt）与本地论文抽取（Hallo-Live / TaoMate-HD）为准，补充性分析均标注「补充/示意」。

白板顶部的第一条对比，是整张地图的地基：Sequential 级联把「文本→语音→视频」拆成互不感知的阶段，每一段误差向下串联；Joint 联合把 Video 与 Speech（乃至完整 Audio）放进同一个生成过程，用共享注意力 / 交叉注意力 / 共享时间步换来原生同步。

Text→TTS→Speech→VidGen→Video

Sequential 范式（Speech-to-Video / 级联）：TTS 先定稿语音，视频生成器再按音频驱动画面（如 TaoMate-HD 表 1 中的 S2V 组：OmniAvatar、StableAvatar、Wan2.2-S2V、LiveAvatar、Hallo3，均假设驱动音频已存在）。优点是各阶段可独立迭代，代价是语音一旦定稿，画面的预期性口型（co-articulation）只能靠视频端硬追，且环境声、拟音、音乐无处安放。

Text→Joint AV 生成（Vid+Speech）→Video + Speech 同步输出

Joint 范式（联合音视频生成，JAVG）：音视频在同一个去噪轨迹里共同演化——LTX-2、Ovi、MOVA、JavisDiT++、MiniMax-H3 构成基础模型层，OmniForcing、Hallo-Live、TaoMate-HD 等再把它们蒸馏/改造为流式层。同步不再靠后处理对齐，而是被写进位置编码、注意力掩码与训练目标。

图 1 · 范式对比：Sequential 把同步问题推给下游 VidGen，Joint 把同步写进注意力与位置编码（把白板顶部的抽象对立具象化为数据通路图）。
深度洞察

「同步」的三种注入点：结构 · 位置 · 目标

把全部工作放在一起看，跨模态同步只有三个入口：① 结构/延迟（因果掩码、look-ahead 窗口、非对称块对齐——OmniForcing 的非对称块因果对齐、Hallo-Live 的 Future-Expanding Attention）；② 位置编码（把音视频映射到同一物理时间轴——MOVA 的 Aligned RoPE、JavisDiT++ 的 TA-RoPE、Ovi 的缩放 RoPE）；③ 训练目标（同步作为可优化信号——JavisDiT++ 的 AV-DPO、Hallo-Live 的 SyncNet reward、JoVA 的嘴部 Flow Matching 损失）。白板后半页的「task angle analysis」与「s-a alignment」两节，本质上就是对这三个入口的正交展开。补充/示意：三个入口的归纳来自跨论文对比，非任何单篇论文的原文表述。

02 音视频基础模型 (Audio-video foundation models)

白板第一大节的六个条目构成「联合音视频基座」的谱系：LTX-2.3、JavisDiT++、OVI、MOVA、VDN、MiniMax-H3。它们回答的是离线高保真联合生成的问题：怎样让语音、音效与画面在同一生成过程中既高质量又同步。

2.1 LTX-2.3（以 LTX-2 代表，arXiv:2601.03233）

命名说明：LTX-2.3 无独立论文；本条以 LTX-2（LTX-2: Efficient Joint Audio-Visual Foundation Model，arXiv:2601.03233，2026-01）代表该路线。TaoMate-HD 的对比表中亦以「LTX-2.3 [1]」指代这一系模型。

方法 / 范式
非对称双流 Transformer：14B 视频流 + 5B 音频流，经双向音视频交叉注意力与 cross-modality AdaLN 共享时间步条件联合生成；配模态感知 CFG（modality-aware CFG）分别控制文本遵循度与声画关联度。替代方案：对称孪生（Ovi）与双塔 Bridge（MOVA）。
Latent 与解码
音视频各自保留 VAE latent，在双流交互中共同演化，最后分别解码：视频出画面，音频出包含 speech、环境声与拟音（foley）的完整音轨。
训练与前置
数据需同步视频 + 音轨 + 完整 caption（含台词、说话人、语言、口音、环境声描述）；双流骨干与文本连接模块共同训练。
优势与证据
开源统一视听基础模型；原报告提供音视频人评与跨模态 guidance 分析，观察到增强跨模态 guidance 可改善同步与语义一致性。第三方口径（TaoMate-HD 表 1）：单卡 0.301 FPS、Desync 0.050，属基础模型组中同步较优者。
路线定位
「非对称双流 + 模态感知 CFG」的工程完备代表；后续 Omni-LiveAvatar 以 LTX-2 为教师蒸馏提速 33 倍（web_landscape.json），是流式层最常用的教师之一。
深度洞察

参数非对称（14B/5B）与 token 稠密度非对称是两回事

LTX-2 给视频 14B、音频 5B，看上去「重视频、轻音频」；但路线笔记（AVG.txt，MOVA 条）明确指出 audio 的 latent 要远比 video 的 latent 稠密——同一秒里音频 token 数量更多。两种非对称方向相反，恰说明二者补偿的是不同瓶颈：参数补的是视觉世界的熵与多样性，token 密度反映的是声学波形的采样率。任何联合注意力设计都必须同时消化这两种失配，否则跨模态注意力会被音频 token 淹没、或让视频 token 饿死。补充/示意：两种失配的对照解读。

2.2 JavisDiT++（arXiv:2602.19163；前身 JavisDiT，arXiv:2503.23377）

方法 / 范式
面向联合音视频生成（JAVG）的统一建模与优化框架：MS-MoE（模态特定专家混合）兼顾跨模态交互与单模态质量；TA-RoPE（时序对齐 RoPE）实现音频与视频 token 的显式帧级同步；AV-DPO（音视频直接偏好优化）从质量、一致性、同步三个维度对齐人类偏好。前身 JavisDiT（2025-03）以分层时空同步先验估计器（HiST-Sypo）引导细粒度同步，并发布 JavisBench（含 10,140 条有声视频描述）与专用同步度量。
核心机制
TA-RoPE 把音视频 token 显式钉到帧级时间格；MS-MoE 在共享骨干里保留模态专属专家，缓解「共享参数伤单模态质量、分开参数伤交互」的两难。替代方案：MOVA 的 Aligned RoPE（映射到统一物理时间尺度）与 Ovi 的缩放 RoPE。
训练与前置
基于 Wan2.1-1.3B-T2V 构建，仅用约 1M 公开样本达到当时 SOTA，显著超越既有开源方法、逼近 Veo3（论文摘要表述）；代码、模型、数据集均已公开（ICLR 2026 接收）。
优势与证据
消融验证三个模块各自收益；以小数据+小骨干取得强对齐，说明同步主要靠表示与目标设计而非堆参数。第三方口径（TaoMate-HD 表 1）：单卡 0.477 FPS；注意其 Desync 1.050 为该表基础模型组最高，评测口径见第 07 节批判。
路线定位
「统一建模 + 偏好优化」的轻量路线旗手；把同步从架构先验（HiST-Sypo）推进到位置编码（TA-RoPE）与偏好目标（AV-DPO）三代演进的完整谱系。

2.3 OVI（Ovi，arXiv:2510.01284）

方法 / 范式
孪生 DiT（twin backbone）块级跨模态融合：scaled-RoPE 负责时序交换、双向交叉注意力负责语义交换；音频塔与强视频模型同构初始化。把音视频作为单一生成过程统一建模，实现自然同步。论文标题为 Ovi: Twin Backbone Cross-Modal Fusion（「OmniVerse」命名未出现在论文正文——据 web_landscape.json 备注）。
Latent 与解码
分别编码、联合去噪：视频用 Wan VAE，音频用 MMAudio 的 VAE，生成 latent 解码为频谱后经 BigVGAN 输出波形。
训练与前置
先预训练音频塔并补充音效数据（音频塔从数十万小时原始音频训练出带说话人身份与情感的语音和逼真音效），再在同步音视频上训练融合；融合阶段冻结 FFN，只更新单模态与跨模态注意力。前置包括通用音频能力、同步过滤、含台词的声景描述。
优势与证据
Verse-Bench 人评中相对 JavisDiT、UniVerse-1 在音视频质量与同步上占优。更关键的下游证据：Hallo-Live 以 Ovi 为教师蒸馏出 20.38 FPS 流式系统，教师的音画同步底座是其被选中的直接原因。
路线定位
「对称双 DiT + 逐层双向交互」的代表；与 LTX-2 的非对称设计互为对照——Ovi 用架构同构换融合简洁性，用音频预训练补音频短板。

2.4 MOVA（arXiv:2602.08794）

方法 / 范式
开源 MOSS Video and Audio 模型：双塔 Wan2.2 视频 DiT + 1.3B 音频 DiT 在文本条件下联合去噪，经双向 Bridge Cross-Attention 交换特征；Aligned RoPE 把两路位置映射到统一时间尺度以保音画同步。整体为 MoE 架构（32B 总参 / 18B 激活），支持 IT2VA（图-文到视频-音频）任务并开放权重与代码。
Latent 与解码
视频与音频保留各自 latent，通过 Bridge 在生成过程中交互；时间位置编码统一到物理时间轴，最终分别解码为视频与含 speech、音效、音乐的完整音轨。audio 的 latent 远比 video 稠密（路线笔记原文），Aligned RoPE 的时间重标定正是对这一失配的直接回应。
训练与前置
先建立音频塔生成能力，再联合训练双塔与 Bridge；Bridge 与骨干采用差异学习率，音视频采用可分别调节的噪声调度。前置：同步音视频、准确台词、声景描述。注意：冻结双塔的暖启动较早达到平台，最终采用联合更新（论文 4.4 节）。
优势与证据
含唇形同步语音、环境感知音效、内容对齐音乐；论文提供语音、音画对齐与人评，并对推理控制消融。第三方口径（TaoMate-HD 表 1）：单卡 0.145 FPS（基础模型组最慢之一），印证 32B MoE 的算力代价。
路线定位
「双塔 Bridge + Aligned RoPE + MoE 规模化」路线；是把「audio latent 稠密」问题明确写进位置设计的代表作。
深度洞察

Aligned RoPE 的本质：把「一个时间轴」变成合同

MOVA 的 Aligned RoPE、JavisDiT++ 的 TA-RoPE、Ovi 的 scaled RoPE 名字不同、机制同源：把两路 token 的位置编码重标定到同一物理时间轴，让「同一时刻」在注意力内积中成为一个可计算的概念。其深意在于——当音频 token 比视频 token 稠密数倍时，朴素拼接位置编号会令 1 秒音频与 1 秒视频在位置空间里错位；统一时间尺度等价于给跨模态注意力签了一份时间合同：查询与键只有落在同一物理时刻附近才容易对上。这也是白板「s-a alignment」一节里「共享 vs 各自 latent」之争的第一条答案：latent 可以分开，时间轴必须统一。补充/示意：合同隐喻与推论。

2.5 VDN（Video DeltaNet，arXiv:2609.20744）

方法 / 范式
视频原生混合注意力：局部 Softmax 注意力 + 双向线性记忆（Video Delta Attention，VDA，每帧更新一次记忆并联合吸收该帧全部空间 token）；两路分支各配独立输出投影与可学习门控校准。关键设计约束：只把混合注意力用于视频-视频交互，涉及文本或音频的交互保留 Softmax。
核心机制
直击视频扩散「长时空 token 序列反复重算、注意力成为算力瓶颈」的问题；线性注意力单独用会丢细粒度交互，故与局部 Softmax 混合，并用分阶段教师对齐训练把新通路渐进注入预训练模型。
训练与前置
实例化于 MiniMax H3：8 步蒸馏 + 优化的 SGLang 推理栈；开源代码与权重（OpenVDN/vdn-minimax-h3）。教师对齐配方保证预训练生成先验不被线性化破坏。
优势与证据
14.3 秒 768p 视频的 DiT 去噪在 8×B200 上仅需 6.70 秒（相对 50 步 dense H3 提速 14.5×）。第三方口径（TaoMate-HD 表 1）：8 卡 2.21 FPS，为基础模型组最快（MiniMax-H3 同硬件仅 0.40 FPS）。
路线定位
「注意力效率」路线：不动生成范式，只换视频-视频注意力内核。对语音-视频的启示是其刻意保留音频 Softmax——音频交互对细粒度敏感，线性化风险大于视频。补充/示意：该取舍对 S-A 对齐的推论。

2.6 MiniMax-H3（arXiv:2609.18323，评测代表条目）

命名说明：MiniMax-H3/Hailuo 无独立模型卡论文，但它是被大量论文引用的真实开源音视频基座（33B，据 web_landscape.json 备注），此处以直接评测它的 arXiv:2609.18323 作代表条目。

方法 / 范式
全模态生成模型：在共享隐空间中结合多模态上下文理解与联合音视生成。TaoMate-HD 图 1 揭示其流式用法：以 T2AV 开场 clip + 陆续 I2AV clip 延伸生成，每 5 秒请求执行 49 步去噪、固定分辨率、传一帧到下一 clip。
核心机制
共享隐空间（shared latent framework）是它区别于双塔路线的最大特征：理解与生成共用一套表示。VDN（2.5 节）与 TaoMate-HD（3.4 节，从 MiniMax-H3 FL2VA 模型做 rank-128 LoRA）都以它为底座改造。
训练与前置
无公开模型卡，训练细节不可考（评测论文只测不训）。推理侧前置为多模态上下文（文本/图像/音/视频输入）与在线 conditioning。
优势与证据
物理世界推理评测（517 实例）：总体成功率 41.97%，视频决策推理最高（56%）、音频消歧最弱（27.4%）。长流质量（TaoMate-HD 表 1）：Temporal 0.872 / Long-range 0.673，音画 Desync 0.000，但 8 卡仅 0.40 FPS。
路线定位
「理解+生成统一基座」路线的锚点模型；也是流式改造（VDN、TaoMate 系）的公共出发点。音频消歧 27.4% 的短板直接呼应白板「60% Audio / 40% Speech」的 A 分布问题——弱结构音频段恰是最难的部分。

03 语音-视频生成 (Speech-Video generation)

白板第二大节把镜头从「离线基座」转向「流式与说话人场景」：OmniForcing、Hallo-Live、Lynn、TaoMate。这一节的共同命题是——把双向联合模型变成可实时交互的因果生成器，同时不丢同步与画质。

3.1 OmniForcing（arXiv:2603.11647）

方法 / 范式
首个把离线双流双向扩散模型蒸馏为高保真流式自回归生成器的框架。四大机制（摘要核对）：① 非对称块因果对齐 + 零截断全局前缀，防多模态同步漂移；② 音频 Sink Token（Identity RoPE 约束），解决因果位移下音频 token 极端稀疏引发的梯度爆炸；③ 联合自强迫蒸馏（Joint Self-Forcing），在长 rollout 中动态自纠 exposure bias 累积的跨模态误差；④ 模态无关滚动 KV-cache 推理。
核心机制
关键诊断：双流架构的模态间极端时间不对称与由此产生的 token 稀疏性，使朴素因果蒸馏严重不稳定。Sink Token 用 Identity RoPE 给稀疏音频流一个「不动点」，非对称块对齐则承认音视频可见性不必对称。
训练与前置
教师为离线双向双流扩散模型；训练含自强迫 rollout（学生自生成历史），推理维持滚动 KV-cache。前置为同步音视频数据与教师权重。
优势与证据
单卡约 25 FPS 实时联合音视生成，同步与画质媲美双向教师（摘要表述）。第三方口径（TaoMate-HD 表 1）：单卡 8.32 FPS、Long-range 仅 0.278（长程色彩/亮度连续性弱，小时级场景会漂）。后续 Salt++ 在 480p 4 步因果设置下视觉/运动质量较 OmniForcing 提升 57%/45%（web_landscape.json）。
路线定位
流式蒸馏路线的奠基工作；Hallo-Live 直接以其为对照（严格块因果掩码被标注为「OmniForcing 式」），其「audio 稀疏性」诊断成为后续所有流式工作的公共议题。
深度洞察

「音频 token 稀疏」与「audio latent 稠密」并不矛盾

MOVA 路线笔记说 audio latent 稠密（token 多），OmniForcing 摘要说音频 token 稀疏（引发梯度爆炸）。两说并存恰恰是白板「s-a alignment」的核心张力：token 数量稠密 ≠ 信息密度高。语音在同一段时间里被切成大量高度冗余的声学帧（数量稠密），但因果位移后「有效新信息」极稀（静音段、拖音、共发音），于是线性记忆/Sink Token 一类机制应运而生。度量 S-A 失配时必须区分「采样密度」与「有效信息密度」，否则 Aligned RoPE（补采样密度）与 Sink Token（补有效信息稀疏）会被误认为在解决同一个问题。补充/示意：两说的统一解读。

3.2 Hallo-Live（arXiv:2604.23632，本地详实）

方法 / 范式
异步双流扩散 + 以人为中心的偏好引导蒸馏（自述为首个把流式双流扩散与偏好引导蒸馏结合的实时文本驱动音视频生成框架）。两大组件：Future-Expanding Attention——每个视频块可看到同步音频 + 一小段未来音素线索（口型的共发音预期）；HP-DMD——用视觉保真（VideoAlign）、语音自然度（AudioBox）、音画同步（SyncNet）三路 reward 加权蒸馏样本。
核心机制
严格块因果掩码下视频只能看到当前与过去音频，而真实口型常先于声学起点（co-articulation）。于是音频侧以扩展噪声输入 za,+ = zat ⊕ zat+1 同时去噪「已提交块 + 临时前瞻块」；前瞻块 Ẫt+1 只作跨模态条件、不直接提交，窗口滑动后被覆盖，不累积投机误差。跨模态掩码（1 视频帧 ↔ r=5 音频 token，前瞻窗 W=1 帧）。
训练与前置
两阶段：Stage I 用冻结 Ovi 教师做双流 ODE 初始化（速度回归，继承联合去噪先验）；Stage II 自回归 self-rollout + 双流 DMD + reward 加权。推理维持音视频 KV cache。教师为 Ovi；数据含台词（<S>…<E> 标注）与音频描述（<AUDCAP>）。
优势与证据
2×H200 上 20.38 FPS、延迟 0.94s，相对教师 Ovi 吞吐 16.0×、延迟降 99.3×；VideoAlign 总分与 Sync Confidence 与教师相当，优于其他加速基线的质效权衡；定性展示真人、多说话人、卡通风格泛化。
路线定位
「结构给延迟、reward 给质量」的双轨路线：Future-Expanding 回答 into-delay 维度（用一块前瞻换口型预期），HP-DMD 回答 loss/reward 维度（reward-tilted 分布允许学生超越教师均值）。直接针对 OmniForcing 的两条痛点（未来音频不可见、激进蒸馏的 mean-seeking 退化）。

3.4 TaoMate（= TaoMate-HD，arXiv:2611.03394，本地详实）

方法 / 范式
渐进分辨率自回归音视频流式生成：每个短片段（chunk）先用两步去噪在低分辨率上确立视频粗结构，最后一步把视频精化到高分辨率，音频在整条轨迹中同步生成（音频 latent 几何全程不变）。每一阶段把其干净估计（clean prediction）传给下一 chunk 的同一阶段作历史，实现 stage-parallel 反对角线流水线。文本窗口推进时保留历史 + 重叠文本（A+B → B+C）做续说，无需 ASR/文本指针即从音频历史推断说话进度。
核心机制
① 渐进生成：N=3、网格 L(480×864)→H(768×1376)，低-高分辨率切换用耦合噪声 Λσ 保持信号/噪声分解；② stage-local KV 历史库：每阶段以零噪声编码本阶段干净估计，粗阶段库与高分辨率终点库分开，长流时固定容量（初始视频作视觉锚 + 最近两 chunk 音视频）；③ 非对称文本条件蒸馏：生成器看新窗口 W₂，fake score 从头看 W₁，real score 用源文本前缀；另加「说完即停」的语音完成样例。
训练与前置
从 MiniMax-H3 FL2VA 模型以 rank-128 LoRA 训练于 10,000 组自建蒸馏对；学生自生成 rollout 上训练；前置为同主题扩展台词、语速映射、ASR+VAD 离线确认的语音终点。部署：stage-parallel 推理。
优势与证据
渐进生成较直接高分辨率提速 1.60×，stage-parallel 部署再提速至 1.9×（8×H20 上 8.99 FPS）；续说训练把 CER 从 30.75% 降到 19.57%（−11.18 pp）；演示 小时级 1376×768 音视频流；流式组内 Temporal 0.913、AudioAes 4.407 最高。
路线定位
「算力放在粗网格、历史放在各阶段」的效率路线；与 OmniForcing（蒸馏成少步因果）正交可叠加——它不减少每 chunk 的语义计算量，而是减少高分辨率计算量并让 chunk 间空隙并行化。

05 任务角度分析 (task angle analysis)

白板的第三块是交叉分析维度：task angle analysis（任务角度分析）。它不是又一个模型，而是审视全部工作的一组透镜：A/S/V 任务拆解、A 的 60% Audio / 40% Speech 分布、SAV/ASV 组织方式、into loss / into delay、loss / reward。以下展开中标注「补充/示意」者为对白板速记的解读与论证，事实部分照引来源。

5.1 A/S/V 任务拆解与 60/40 的 A 分布

把「音视频」拆成 A（Audio，环境声/拟音/音乐）、S（Speech，含语言的语音）、V（Video） 三个任务面后，白板给出一个关键的经验分布：A 通道内部约 60% 是非语音音频、40% 是语音（白板经验值，非论文统计；标注「补充/示意」）。这个 60/40 有两层含义：

其一，结构不对称。S 是强结构信号——有音素序列、词汇、说话人身份、韵律，可被 ASR/TTS/文本精确监督；A 的 60% 是弱结构信号——声景、拟音、音乐只有场景级语义。模型必须同时握住强结构与弱结构先验，这解释了为什么几乎所有系统都做「音频塔预训练 + 联合微调」两段式（Ovi：数十万小时原始音频预训练音频塔；UniTalking 消融显示音频预训练对最终音质关键；MOVA：先建立音频塔生成能力再联合训练）。

其二，弱结构恰是短板。MiniMax-H3 的物理推理评测里，音频消歧最弱（27.4%）、视频决策最强（56%）——模型对「看得见的因果」远好于对「听得出来的因果」。60% 的 A 分布意味着这一短板覆盖了音频任务的多数面。Unison 的应对是显式把 speech/SFX 两路 latent 分开、各自预测再协调；Soundwich 干脆把人声/音效/背景声做成可独立编辑的多轨。补充/示意：60/40 与短板数据的因果关联论证。

5.2 SAV / ASV：组织顺序的两种答案

白板速记「SAV / ASV」指向任务组织方式之争（补充/示意：解读）——ASV 把 Audio 视为整体、Speech 只是音轨里的一段（Ovi、LTX-2、MOVA：一条完整音轨含 speech+环境声+音乐）；SAV 把 Speech 提为一等公民、与非语音 Audio 并列再联合 Video（Unison 的 speech/SFX 双 latent、MM-Sonate 的统一指令-音素输入、JoVA 的嘴部区域 Flow Matching 损失、UniTalking 先 TTS 预训练音频分支）。判据是场景：只要求唇音同步的数字人（S2V 一族）天然是 ASV；要求「说完话后杯子放下还有碰撞声」的复杂声景则必须 SAV。代价也清晰：SAV 需要分离器（Unison 用 Mel-Roformer 分离人声/音效）或强标注（台词、说话人、口型关键点），数据前置成本高。

5.3 into loss / into delay / loss / reward：约束的三种去处

白板的「into loss/delay」「loss/reward」两组速记，指向跨模态约束进入系统的两条轴（补充/示意：解读）：

into loss（写进损失）
同步/对齐作为可微目标：JoVA 的嘴部区域 Flow Matching 损失、OmniVAE 的片段级对比学习、JavisDiT++ 的 AV-DPO、Hallo-Live Stage I 的速度回归初始化损失。优点是梯度信号直接；缺点是需要可微的对齐度量或标注（嘴部关键点、同步配对）。
into delay（写进结构与延迟）
同步作为可见性/延迟预算：OmniForcing 的非对称块因果对齐与零截断全局前缀、Hallo-Live 的一块前瞻（W=1）、TaoMate-HD 的重叠文本窗口、LynnReal-Omni 的边界重叠。优点是推理期免费获得预期性；缺点是延迟预算一旦定死，快慢场景共用一个 W。
loss（回归/分布匹配）
优化以模仿为主：Flow Matching 速度回归、DMD 分布匹配（OmniForcing、Hallo-Live、TaoMate-HD 均以 DMD/自强迫为主体）。稳定、可复现，但受限于教师流形——vanilla 蒸馏会 mean-seeking。
reward（奖励/偏好）
优化引入人类中心信号：HP-DMD 以 VideoAlign/AudioBox/SyncNet 三路 reward 加权（Hallo-Live 式 (6)-(10)）、AV-DPO 偏好对齐（JavisDiT++）、AVC-Reward 可作在线 RL 信号（web_landscape.json）。优点是能超越教师均值；缺点是 reward 模型本身的偏差会被放大（见第 07 节）。

Eq.1 · HP-DMD 的 reward 加权蒸馏（Hallo-Live 式 (6)-(10)，论文原式）
$$ z_{i,k}=\frac{R_{i,k}-\mu_k}{\sigma_k+\epsilon},\qquad w_i=\exp\Big(\sum_{k=1}^{K}\beta_k z_{i,k}\Big),\qquad \mathcal{L}_{final}(\theta,x_i)=w_i\cdot\mathcal{L}_{dmd}(x_i) $$
直觉：三路奖励 Ri,k（k ∈ {视觉保真 VideoAlign，语音自然度 AudioBox，同步 SyncNet}）先在批内标准化为 zi,k，再指数聚合成样本权重 wi；好的样本对蒸馏梯度贡献更大。等价于拟合 reward-tilted 目标分布 p* ∝ pT·exp(R) 而非教师分布 pT——这是「loss/reward」轴上学生超越教师均值的机制化解释。βk 控制各模态贡献。
深度洞察

loss、delay、reward 是同一个同步问题的三种货币

同一份「音画要同步」的知识，可以记在三本账上：loss 账（可微、需标注）、delay 账（推理期结构、吃延迟预算）、reward 账（可无标注、吃奖励模型质量）。2025-2026 的路线演化呈现出清晰的兑换趋势：早期工作集中把同步记入 loss（对比学习、嘴部损失），流式化浪潮迫使同步改记入 delay（因果掩码、前瞻窗），而偏好对齐兴起后同步又开始记入 reward（HP-DMD、AV-DPO）。三本账各有兑换损耗：loss 需要配对数据，delay 牺牲延迟或引入投机，reward 引入 reward hacking 风险。当前没有工作同时优化三本账的兑换率——这是一个可切入的空白（见 Q1）。补充/示意：跨论文演化论证。

06 语音-音频对齐 (s-a alignment)

白板最后一块交叉维度是 s-a alignment（语音-音频对齐）。注意它与「音画同步」不同轴：这里问的是 S 与 A 这两个声学模态之间——以及它们与 V 的三方关系——如何对齐。白板速记包括：S+V 对齐、共享 vs 各自 latent、audio latent 更稠密、Aligned RoPE / 对比对齐 / 共享 DiT。

6.1 S+V 对齐：为什么语音-视频是最硬的一对

唇音同步是毫秒级约束（SyncNet 度量、LSE-C/LSE-D），而环境声与画面只需事件级一致（AVC-Reward 的三级一致性：全局叙事/事件级时序/细粒度属性）。于是所有语音-视频系统都把预算花在 S-V 边界上：Hallo-Live 用 r=5 音频 token/视频帧的细粒度跨模态掩码 + 前瞻；JoVA 加嘴部区域损失；MM-Sonate 用统一指令-音素输入保证严格语言与时序对齐；TaoMate-HD 用 CER（Whisper 转写对比台词）作为语音正确性的直接度量。反过来说，S-A 对齐（语音与其背景声）几乎无人单独度量——Unison 的 DS 失同步指标与 AVC-Reward 是少数例外。补充/示意：度量空白的观察。

6.2 共享 vs 各自 latent：证据已经偏向「各自」

AVTok 的对照实验是白板上最硬的一条证据：vanilla 尝试过共享 latent、共享参数，效果不好；最终双流（各自 token 序列 + 共享编解码器主干与码本）重建更好。OmniVAE 同样保留两路可重建 latent，只在上面加片段级双向对比与语义蒸馏。到生成侧，全部主力模型（LTX-2 / Ovi / MOVA / NAVA / UniTalking / JoVA）无一例外采用「各自 VAE latent + 融合层交互 + 各自解码」。结论：共享的正确层级是时间与语义坐标（Aligned RoPE、对比对齐），而非采样表示本身。

6.3 audio latent 更稠密：三种补偿机制

路线笔记原文：「audio 的 latent 要远远稠密 video 的 latent」。稠密不是免费的——跨模态注意力的算力与信噪比都随音频 token 数倾斜。三种补偿各有代表：

位置重标定（Aligned RoPE / TA-RoPE / scaled RoPE）
MOVA 把两路映射到统一时间尺度；JavisDiT++ 显式帧级；Ovi 缩放 RoPE 时序交换。补偿的是位置错位。
表示级对齐（对比 + 蒸馏）
OmniVAE 在各自 latent 上加片段级双向对比学习并从语义教师蒸馏；AVTok 共享码本但保留各自序列。补偿的是语义坐标错位。
稀疏性保护（Sink Token / 非对称对齐）
OmniForcing 的音频 Sink Token（Identity RoPE）与非对称块因果对齐，针对因果化后音频有效信息稀疏引发的梯度爆炸与同步漂移。补偿的是有效信息密度失衡（注意与 token 数量稠密并不矛盾，见 3.1 节洞察）。
共享 DiT（单塔融合）
JavisDiT（联合 DiT + 分层时空先验）、Apollo（单塔统一 DiT 块 + Omni-Full Attention）、DaVinci-MagiHuman 的单流简化：干脆不分流，用紧致共享换取对齐。代价是单模态容量与预训练复用受限。替代方案：双塔 Bridge（MOVA）介于两极之间。

Eq.2 · 时间对齐 RoPE 的统一映射（补充/示意，综合 MOVA/JavisDiT++/Ovi 思路）
$$ \tau_m(i) = \frac{i}{f_m}\quad\text{（token } i \text{ 的物理时刻，} f_m \text{ 为模态 } m \text{ 的 token 率）};\qquad \theta_{m,i} = \omega\cdot \tau_m(i) $$
直觉：不对齐时，音视频各自按 token 序号加旋转角，1 秒音频（token 多）与 1 秒视频（token 少）在位置空间错位；统一映射后，跨模态注意力只在物理时刻相近处得分高。MOVA 的 Aligned RoPE（统一时间尺度）、JavisDiT++ 的 TA-RoPE（显式帧级）、Ovi 的 scaled RoPE（时序交换缩放）是同一思想的三种实现。此式为示意性综合，非任一论文原式；真实实现含各模型自己的频率设计。
深度洞察

S-A 对齐的终极形态可能是「一个时间轴 + 多个信息通道」

把本节证据串起来：latent 该分（AVTok/重建证据）、时间轴该合（三种 RoPE）、语义坐标该对齐（OmniVAE 蒸馏）、稀疏流该保护（Sink Token）。这四条合起来指向一个架构原则：对齐的对象不应是表示本身，而是表示所依附的坐标系——物理时间轴 + 共享语义坐标，其余保持模态自由。这与白板「S+V 对齐、共享 vs 各自 latent」的速记完全吻合，也解释了为什么「共享 latent」的 vanilla 尝试失败而「共享时间尺度」的 Aligned RoPE 成功：前者共享了不该共享的（信息载体），后者共享了必须共享的（坐标系）。补充/示意：原则性归纳。

07 深度洞察 & 批判评估

把全图最有张力的两条证据链单独拎出来，并给出不回避代价的评估。

深度洞察

流式化的本质是「历史表示」问题，而非「步数」问题

四个流式工作对「跨 chunk 传什么历史」给出了四个答案：OmniForcing 传滚动 KV-cache（模态无关）；Hallo-Live 传已提交块 + 覆盖式前瞻块；LynnReal-Omni传有界 latent 历史 + 边界重叠；TaoMate-HD 传各阶段干净估计（零噪声编码）。步数只是表象——4 步还是 3 步由蒸馏决定，而长时一致性、续说能力、能否 stage-parallel 取决于历史表示。TaoMate-HD 的干净估计尤其优雅：它让「去噪未完成的中间产物」提前成为可用上下文，把 chunk 间等待时间从 critical path 上拆掉（1.6× 空间加速 + 1.9× 部署加速的乘法由此而来）。补充/示意：四方案的统一抽象。

深度洞察

蒸馏是新的「第二次训练」：学生在 reward 帮助下可以越过教师

Hallo-Live 的 HP-DMD 把目标分布从 pT 改成 p* ∝ pT·exp(R)，理论上允许学生在教师流形的高奖励区域过采样、超越教师均值；OmniForcing 的联合自强迫则让学生在自生成历史上学习自纠误差。两者合起来说明：蒸馏阶段不再只是压缩，而是吸收人类偏好与暴露偏差修正的第二次训练。TaoMate-HD 的续说训练（CER 30.75%→19.57%）进一步表明，流式特有的能力（跨文本窗口续说、说完即停）只能在蒸馏/后训练阶段获得，教师根本没有这个任务。补充/示意：趋势性论证。

批判评估

效率数字不可比：计时区间、硬件、分辨率三重口径混乱

表面看 25 FPS（OmniForcing）/ 20.38 FPS（Hallo-Live）/ 8.99 FPS（TaoMate-HD parallel）可横比，实际不然：硬件覆盖单卡（型号各异）、2×H200、8×H20、8×B200；分辨率从 768×512、768p 到 1376×768；计时区间不同（TaoMate-HD 自述其区间含文本预编码外的解码，而 MiniMax-H3/VDN/Lynn 含在线 conditioning 与 encode/mux）。连 TaoMate-HD 自己的「22.4× 相对 MiniMax-H3 吞吐比」也是在各自区间下的比值。本页表格只做量级排序，任何严格效率结论都需重测。

批判评估

reward 路线的循环依赖：用模型评价模型

HP-DMD 的三路奖励（VideoAlign、AudioBox、SyncNet）与 AV-DPO 的偏好数据都是模型产物。风险有三：① reward hacking——学生学会讨好 SyncNet 而非真正同步（SyncNet 本身可被对抗）；② 教师缺陷继承——Hallo-Live 从 Ovi 初始化，Ovi 的口型/韵律偏差会沿蒸馏传下去；③ 人评缺位——Hallo-Live 自述质量「comparable」是在自动指标维度，大规模人评未见。同类问题也见于 UniAVGen（情绪一致性由多模态模型打分，笔记明确「值得补充人类盲评」）。奖励越多，越需要独立于奖励体系的人类验证。

批判评估

全模态基座的「理解」仍很浅：41.97% 总成功率

MiniMax-H3 的物理推理评测（517 实例）总体成功率仅 41.97%，音频消歧 27.4%——共享隐空间并未自动带来跨模态推理能力。这打击了「统一表示 ⇒ 涌现理解」的乐观叙事：联合生成质量的进步（Desync 0.000）与理解能力的进步（41.97%）并不同步。把生成基座当世界模型用，证据远未就绪。

08 自主科研问题

从白板两条交叉维度直接生长出的四个可探究问题，每个都锚定具体证据缺口。

自主科研问题 · Q1

同步约束应记入 loss、delay 还是 reward？三者的最优兑换率是什么？

未知与意义：三本账（05.3 节）目前被各工作单独使用，无任何工作联合优化并度量兑换损耗。

理论分析：loss 受限于可微对齐度量与标注密度；delay 受限于延迟预算（Hallo-Live 固定 W=1，快慢场景同权）；reward 受限于奖励模型误差的指数放大（Eq.1 中 exp 会放大 β 加权的偏差）。

连接：Hallo-Live（delay+reward）、JavisDiT++（loss+reward）、OmniForcing（delay+loss）恰好各占两两组合，缺三者联立。

探究方向：构造三轴消融：固定参数量与数据，扫 (loss 权重, 前瞻窗 W, reward 温度 β)，测 SyncNet/人评/延迟 Pareto 面，检验是否存在内点最优而非角点解。

自主科研问题 · Q2

audio latent 稠密性与有效信息稀疏性的失配，能否被一个可计算指标统一描述？

未知与意义：MOVA 说 audio latent 稠密、OmniForcing 说 audio token 稀疏，两者都对但维度不同（3.1 节洞察）；缺乏统一量度导致 Aligned RoPE 与 Sink Token 被混为一谈。

理论分析：可用「每物理秒 token 数 × 每 token 熵」的二维刻画；稠密-低熵（语音拖音段）对应 Sink Token 需求，稠密-高熵（瞬态音效）对应位置重标定需求。

连接：AVTok 的「共享 latent 效果不好」可能正是熵失衡的表现；MiniMax-H3 音频消歧 27.4% 最弱也指向音频信息利用不足。

探究方向：在 Ovi/MOVA 上探针测量两模态逐位置熵与跨模态注意力质量的相关性，再按熵分段替换对齐机制，验证指标的预测力。

自主科研问题 · Q3

流式历史表示：滚动 KV、覆盖式前瞻、有界 latent、干净估计——各自的失效边界在哪里？

未知与意义：四种历史表示（07 节洞察）没有统一评测；OmniForcing 的 Long-range 0.278 与 TaoMate 的 0.983 暗示差异巨大，但口径不可比。

理论分析：历史表示在「信息保留、算力、误差累积」三角里各占一角：KV-cache 保真但显存线性、干净估计可复用但有估计误差、有界 latent 恒定开销但丢长程、前瞻块免累积但吃延迟。

连接：TaoMate-HD 的固定容量库（视觉锚 + 最近两 chunk）是显式的三角权衡；Hallo-Live 的覆盖式前瞻回答了「投机不累积」约束。

探究方向：同一教师（Ovi 或 MiniMax-H3）上实现四种历史接口的受控对比：扫 10 分钟~1 小时时长，测 CER、LSE-C、Long-range、显存与首包延迟曲线。

自主科研问题 · Q4

60/40 的 A 分布下，Speech 与非语音 Audio 应该分 latent 还是合 latent？

未知与意义：Unison 用显式 speech/SFX 双 latent（消融 PQ 6.12→6.34、DS 0.19→0.08），Ovi/LTX-2 用单一音轨；两种做法没有在同一基准上正面比较。

理论分析：S 强结构（可被文本/音素监督）、A 弱结构（仅场景级描述）；分轨使监督各得其所但需要分离器（Mel-Roformer）与协调机制（Bi-ACA 门控），合轨省前置但让弱结构段被强结构段主导。

连接：这正是 SAV/ASV 之争（05.2 节）；MM-Sonate 的统一指令-音素输入提供了第三条路——不分 latent 但分输入通道。

探究方向：以 Unison 与 Ovi 为两端，在同数据上做「1/2/3 路音频 latent」扫描，按 60/40 混合比例与场景复杂度分桶评测语音可懂度（WER）、音效自然度与互扰指标。

# Hallo-Live 式 Future-Expanding Block-Causal Mask（据论文式 (5) 重写）
# 1 视频帧对齐 r=5 个音频 token；W 为前瞻帧数（论文用 W=1）
def future_expanding_mask(num_v_frames, r=5, W=1):
    num_a = num_v_frames * r
    mask = np.zeros((num_v_frames, num_a), dtype=bool)
    for t in range(num_v_frames):
        # 视频帧 t 可见音频 token 序号 ≤ r*(t+W)：同步 + 前瞻 W 帧
        mask[t, : r * (t + W + 1) - 1] = True
    return mask  # W=0 时退化为严格块因果（OmniForcing 式）

# HP-DMD：reward 加权的双流 DMD 一步（据 Hallo-Live 式 (6)-(10) 重写）
def hp_dmd_step(student, prompts, betas=(0.4, 0.3, 0.3)):
    x = student.sample(prompts)                      # 学生自生成音视频样本
    R = stack([videobox(x), audiobox(x), syncnet(x)])  # K=3 路奖励
    z = (R - R.mean(0)) / (R.std(0) + 1e-6)          # 批内标准化
    w = exp(z @ betas)                                # 样本权重 w_i
    loss_dmd = dmd_loss(real_score, fake_score, x)    # 分布匹配项
    return (w * loss_dmd).mean()                       # 拟合 p* ∝ p_T·exp(R)

# TaoMate-HD 式 stage-local 干净估计与 KV 提交（据其式 (1)(3) 与 Algorithm 1 重写）
def chunk_stage(u, sigma, sigma_next, v_hat, stage, banks):
    euler = u + (sigma - sigma_next) * v_hat         # Euler 前进
    x_clean = u + sigma * v_hat                       # 干净估计：零噪声端点
    banks[stage].write(encode(x_clean, noise=0))      # 同阶段下 chunk 复用
    return euler, x_clean
